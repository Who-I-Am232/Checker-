# Різке переміщення та можливий телепорт

Сенсор працює у серверному `CA_MovementSampler.c`, приблизно раз на секунду.
Він отримує контрольований `ChimeraCharacter` через `PlayerManager`, а для
водія/пілота — транспорт із `PilotCompartmentSlot.GetVehicle()`. Пасажири,
відсутній персонаж і перехід між місцями не використовуються для цього виміру.
Це спостереження серверного стану, який теж може коригуватися реплікацією.

Пара позицій дійсна лише для того самого персонажа, транспорту, режиму та
відомого audited UID. Зміна будь-якого з них скидає baseline. Респавн із новим
персонажем, посадка/висадка та перепідключення тому не порівнюються зі старою
точкою. Після скидання діє 10 с grace. Якщо ваш мод робить респавн переміщенням
того самого entity, потрібно інтегрувати явне скидання нижче.

Інтервал береться з реального серверного часу. Розрив понад 2500 мс або менш
ніж 250 мс скидає baseline; це зменшує шум при зависанні сервера. Перші 60 с
сесії не оцінюються. Лаг або корекція всередині допустимого інтервалу все ще
можуть створити спрацювання — ці перевірки не усувають усі хибні сигнали.

## Пороги

Для спрацювання одночасно потрібні мінімальна відстань **і** середня швидкість.

| Режим | Попередній поріг у моді | Поріг аналізатора за замовчуванням |
|---|---|---|
| FOOT | 30 м і 20 м/с | 80 м і 35 м/с |
| VEHICLE | 100 м і 100 м/с | 200 м і 200 м/с |

Пороги аналізатора: `movement_foot_distance_m`, `movement_foot_speed_mps`,
`movement_vehicle_distance_m`, `movement_vehicle_speed_mps` у `config/analyzer.json`.
Інтервал: `movement_min_delta_ms`/`movement_max_delta_ms`. Повтор для того самого
гравця й tracked entity у межах сесії пригнічується на `movement_cooldown_ms`
(30000 мс за замовчуванням). Інші гравці не пригнічуються цим cooldown.

Мод записує лише кандидати після попередніх порогів. Пониження порогів Python
нижче порогів колектора не поверне незаписані виміри; для цього змініть
`CA_MovementSampler.c` та перекомпілюйте addon. Розширення допустимого інтервалу
Python понад 2500 мс також не змінить ліміт колектора.

`AVG_SPEED` — відстань між двома точками / час. `INST_SPEED` — модуль поточної
фізичної швидкості. Їхня різниця корисна для розгляду, але не є доказом чита.
Недоступна фізична швидкість показується як `н/д`. Початкові пороги потрібно
звірити з вашими модами техніки, літаками, катапультуванням, фізикою та GM.

## Легальні телепорти

Сенсор не може автоматично розпізнати всі сторонні моди телепорту. У **вже
перевіреному серверному коді**, безпосередньо перед дозволеним переміщенням,
викличте адаптер:

```c
CA_Runtime audit = CA_Runtime.Get();
if (audit)
    audit.AllowMovementReset(playerID, 5000, "authorized_fast_travel");
// Here the existing permission-validated server action performs the movement.
```

`playerID` має походити з підтвердженого серверного контексту дозволеної дії.
Не відкривайте цей метод через новий клієнтський RPC і не робіть постійних
винятків для всіх адміністраторів. Метод обмежує duration до 1–60 с, записує
`movement_reset` і скидає baseline під час вказаного вікна; після останнього
скидання ще діє стандартний grace. Перед переміщенням керованої техніки
викликайте адаптер для фактичного водія/пілота.

## Покриття і приймання

Рух між вимірами з поверненням назад, коротке/повільне переміщення, рух під час
grace, техніка без водія та пасажири не охоплюються. Стан обмежено 256 гравцями;
перевищення ліміту створює `telemetry_loss`. Це O(кількість гравців) читань
позицій за tick, без окремого просторового пошуку для кожного персонажа.

На стенді перевірте нормальний біг, падіння, зіткнення, швидку техніку, посадку,
зміну місця, респавн, reconnect, розрив sampling і легальний GM teleport з
адаптером. Потім після grace виконайте контрольоване переміщення на 700 м
штатним серверним тестовим кодом без адаптера: має виникнути кандидат та alert
за відповідного інтервалу. Використання чит-ПЗ для тесту не потрібне.

Сигнатури API звірено, але **компіляція та ці тести в грі ще не виконані**.
Python-тести перевіряють аналіз записів, а не роботу таймерів/місць у рушії.
