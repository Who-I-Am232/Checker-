# Перевірки та приймання

Дата локальної перевірки: 2026-11-11.

## Виконано

| Перевірка | Результат |
|---|---|
| `python3 -m unittest discover -s tests -v` | **34 тести пройдено** |
| `python3 -m py_compile analyzer/checker.py examples/make_demo.py` | Успішно |
| Генерація демонстраційної телеметрії | 34 синтетичні події |
| CLI аналіз демонстрації | 2 очікувані спрацювання, без дублювання |
| Звірка основних ігрових сигнатур | Офіційний source snapshot 1.9.0.37; посилання в API_SOURCES.md |
| Пошук встановленого Reforger/Workbench у середовищі | Виконувані програми не доступні |

Тести перевіряють кореляцію init/placement і композицій, старі parent-actions,
warmup, baseline, просторове групування та часові вікна, повторні hitzone-події,
різні цілі вибухової шкоди, повторні тригери, відокремлення сесій, пропуски seq,
ліміти пам'яті, whitelist/watchlist, невідомого автора, JSON з Unicode/переносами,
часткові рядки при live-читанні, обрізання файлів, порядок ротації, великі вхідні
файли, неправильні конфігурації та захист raw-файлу від перезапису output.

Демонстрація: `examples/events-demo-0.jsonl` → `examples/alerts-demo.jsonl`.
Ці файли створено генератором, а не ігровим сервером. Успішні тести Python не
підтверджують компіляцію Enforce, повноту hooks, ефективність проти конкретного
чита або прийнятне навантаження на цільовому сервері.

## Потрібно виконати в грі

- [ ] Записати точну версію гри, сценарій, список модів та порядок їх підключення.
- [ ] Скомпілювати addon у відповідному Workbench без помилок.
- [ ] Запустити чистий Conflict і отримати `session_start` та `heartbeat`.
- [ ] Повторити з повним набором серверних модів; перевірити всі `super` chains.
- [ ] Створити штатну споруду та техніку: отримати raw init і placement, перевірити UID.
- [ ] Розмістити композицію: перевірити реальні parent-ID і кореляцію дочірніх об'єктів.
- [ ] На стенді створити тестовий prefab через серверний код без звичайного
  будівельного маршруту: побачити init; серія повинна дати unattributed alert.
- [ ] Створити тестовий query-visible prefab без editable-компонента в уже
  просканованій ділянці: отримати scan_new. Перший baseline не має дати alert.
- [ ] Перевірити щільну забудову: scan_incomplete повинен бути видимим і не
  перетворювати частковий знімок на baseline або масовий spawn.
- [ ] Підірвати заряд; окремо — гранату/снаряд. Зафіксувати, які саме сенсори
  спрацювали, включно з вибухом без цілей та secondary explosions.
- [ ] Пошкодити багато hitzone одного об'єкта: лічильник різних цілей не зростає.
- [ ] Перевірити застарілий instigator після disconnect/reconnect: не має
  підставлятися UID нового власника player ID.
- [ ] Перевірити видалення entity до flush і зміну карти/перезапуск сценарію.
- [ ] Перевірити довге persistence-відновлення та підібрати warmup.
- [ ] Перевірити заповнення черги, ротацію, відсутність права запису, бюджет
  файлів і зупинку телеметрії — усі мають бути видимі адміністратору.
- [ ] Зняти серверний FPS/час кадру з `-logStats 10000` до/після за однакового
  навантаження; окремо протестувати сканер увімкненим і вимкненим.
- [ ] Перевірити нормальний інтенсивний бій/артилерію/GM, налаштувати пороги,
  зафіксувати частоту хибних спрацювань і відомі пропуски.

Тестове створення об'єктів виконувати штатними інструментами адміністратора або
власним кодом у контрольованому стенді. Для цих перевірок стороннє чит-ПЗ не потрібне.

## Умови переходу до бойового сервера

Прийнятний результат — успішна компіляція цільової версії, контрольні raw-події
для кожного заявленого сенсора, відома ціна для FPS і перевірена обробка легальних
маршрутів. Спочатку залишайте режим спостереження й ручний розгляд. Навіть після
цього спрацювання саме по собі не є доказом запуску стороннього ПЗ гравцем.
