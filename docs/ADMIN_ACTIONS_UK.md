# Адміністратор, Game Master і непідтверджена дія

Checker окремо записує **роль гравця** та **походження конкретної дії**.
Роль ADMIN не створює постійного винятку для всіх дій гравця. GAME_MASTER може
бути делегованою роллю без статусу адміністратора сервера.

| Позначка в Discord | Що підтверджено | Обробка |
|---|---|---|
| `GM_AUTHORIZED` | Серверний GM-маршрут конкретного розміщення або явний зв'язок ефекту через серверний адаптер | Окрема група лічильників, severity info, збереження доказів |
| `GM_ORIGIN` | Джерело пошкодження/тригера — об'єкт або його нащадок, раніше створений через GM | Дозвіл на поточний ефект не встановлено; звичайна перевірка, без винятку |
| `UNVERIFIED` | Немає достатнього запису перевірки дозволу | Звичайні правила й ручний розгляд; це не доказ чита |

## Перевірка штатного GM-розміщення

У `OnEntityCreatedServer` після успішного callback беруться серверні manager і
mode. `CA_AuthorityTracker` перевіряє:

- режим EDIT належить саме цьому manager через `FindModeEntity`;
- manager і mode не позначені limited;
- серверна роль — ADMIN/SESSION_ADMINISTRATOR або GAME_MASTER;
- UID уже отриманий після успішного backend audit;
- об'єкт належить основному світу.

ID гравця береться з manager. Офіційний базовий CreateEntityServer також
перевіряє відповідність переданого player ID власнику manager до створення.
Checker зберігає `authorization_id`, ID конкретного об'єкта та знімок імені,
UID і ролі виконавця. Пізніша зміна власника player slot не змінює цей знімок.
Для init/composition дочірнього об'єкта контекст береться лише зі зіставленого
placement у стандартному кореляційному вікні 2500 мс.

Розміщення через Conflict для звичайного гравця зберігає відомий маршрут,
але не отримує ознаку GM. Якщо callback або дані дозволу відсутні, Checker
залишає `UNVERIFIED`. Статус ADMIN у записі руху теж не дозволяє телепорт сам
по собі; для легального teleport існує [окремий адаптер](MOVEMENT_UK.md).

## Game Master FX

Імовірно зазначений мод — [Game Master FX, 5994AD5A9F33BE57](https://reforger.armaplatform.com/workshop/5994AD5A9F33BE57)
автора ceo_of_bacon. Workshop описує вибухові, вогневі, димові й артилерійські
ефекти. Точний перелік модів та версії цільового сервера ще не підтверджені.

Для FX, які проходять штатний placement, є загальна інтеграція вище. Для
пошкоджень `Capture` зберігає слабкі посилання на damageSource та до 7 його
предків у момент події; для trigger — на його об'єкт і предків. Точний збіг
живого об'єкта з GM-реєстром дає лише `GM_ORIGIN`. Адмін міг створити машину,
якою пізніше скористався інший гравець: це не підтверджує дозвіл на її вибух.

Для підтвердження конкретного запланованого GM-ефекту потрібен виклик із
**перевіреного серверного генератора ефектів** після створення джерела,
до його спрацювання:

```c
CA_Runtime audit = CA_Runtime.Get();
if (audit)
    audit.RegisterGMEffectSource(projectile, authorizedGenerator);
```

`authorizedGenerator` має вже бути зареєстрований успішним GM-placement.
Цей метод переносить знімок конкретної GM-дії на точний projectile, без пошуку
за радіусом або близьким часом. Для прямого ефекту генератора допустимі однакові
аргументи. Виклик має робити серверний код дозволеної операції; відкривати його
для клієнтського RPC не можна. Наявність серверного методу не є перевіркою
дозволу стороннього RPC — це обов'язок його обробника.

**Готового перевіреного адаптера внутрішніх класів Game Master FX тут немає:**
їхні вихідні файли/точні prefab цільової версії не надані, загальну інтеграцію
ще не перевірено в грі. Не стверджується, що кожен його авіаудар, снаряд чи
ефект автоматично отримує GM_AUTHORIZED. Відокремлений projectile без зв'язку
залишиться UNVERIFIED. Короткоживучий або видалений source може не отримати
навіть GM_ORIGIN. Реалізований серверний метод — точка для такого адаптера.

## Межі та приймання

Реєстр має максимум 1024 джерела, lifetime 60 с від початкової GM-дії. Link не
продовжує lifetime. При перевищенні бюджету пишеться `telemetry_loss`, статус
не підвищується автоматично. Посилання на об'єкт і перевірка його identity
захищають від простого повторного використання entity ID. Resolve повторюється
при flush для ефектів, що спрацювали безпосередньо перед завершенням callback;
допустиме відставання реєстрації — до 2500 мс. Видалення source до resolve
може залишити подію без підтвердженого зв'язку.

Підтверджені й непідтверджені події мають окремі вікна та cooldown. Адмінський
спавн не додається до кількості підозрілих об'єктів іншого гравця в тій самій
ділянці й не блокує його сповіщення. Підтверджені спрацювання показуються як
інформаційні GM-дії; вони не видаляються. Перевищення порога законним GM може
потребувати перевірки навантаження або зловживання повноваженнями.

На стенді перевірте ADMIN, делегованого GM, звичайного гравця, відкликані права,
placement із різних editor modes, відсутній UID, композиції, окремі projectile,
видалення source до flush, строк дії та незв'язаний вибух біля легального FX.
Окремо перевірте, що фактичний мод викликає штатний callback із `super`.
Компіляція Enforce та ці перевірки в грі ще не виконані. Компрометація сервера
або його системи дозволів може підробити самі дані походження.

## Локальний приклад

```bash
python3 examples/make_authority_demo.py
python3 analyzer/checker.py --input examples/events-authority-0.jsonl --config config/analyzer.json --output runtime/authority-alerts.jsonl
python3 notifier/discord_bot.py --input runtime/authority-alerts.jsonl --server-id server-1 --server-name "Server 1"
```

Це синтетичні записи: 44 події → 5 повідомлень із різними статусами. Приклад
демонструє формат і аналізатор, а не працездатність сенсорів у Game Master FX.
