# ConflictAudit / Checker-

Прототип спостереження за підозрілими подіями **Arma Reforger Conflict**: серверний
мод Enforce Script + аналізатор Python + сповіщення в Discord через webhook.
Колектор створює власну телеметрію,
тому відсутність події у звичайному `console.log` не заважає аналізу, **якщо подію
бачать встановлені сенсори**.

**Стан: Python-аналізатор і Discord notifier перевірено локальними автоматичними
тестами; реальну доставку в Discord ще не перевірено. Ігровий мод ще не
скомпільовано в Workbench і не перевірено в Arma Reforger. Це вихідний код для
стендових випробувань, не готовий перевірений Workshop-реліз.** API звірено з
офіційними скриптами версії **1.9.0.37**. Версія цільового сервера невідома.

Мод не визначає, яку програму запущено на ПК гравця. Він позначає аномальні
серверні спостереження для адміністратора. Автоматичних банів, кіків, видалення
об'єктів і сканування процесів немає. Discord-доставка вмикається окремо через
`--send`; за замовчуванням notifier лише показує повідомлення в терміналі.

## Що реалізовано

- Окремі JSONL-журнали: `$profile:ConflictAudit/events-<session>-<part>.jsonl`.
- Спостереження за ініціалізацією об'єктів із `SCR_EditableEntityComponent`.
- Спостереження за штатними маршрутами розміщення у Conflict та редакторі.
- Обмежене порівняння знімків об'єктів у ділянках біля гравців, зокрема об'єктів
  без editable-компонента, якщо вони доступні просторовому запиту та мають prefab.
- Події вибухових пошкоджень і виклики тригерів окремих вибухових пристроїв.
- Вимірювання різких переміщень персонажів та керованої ними техніки:
  відстань, реальний інтервал, середня й поточна фізична швидкість.
- Координати, prefab, час, ID об'єкта, ID сесії та джерело атрибуції.
- Правила для масового створення об'єктів, невідомого шляху їх появи, серій
  тригерів, групових вибухових пошкоджень і втрати телеметрії.
- Прив'язка до гравця за серверним callback, engine instigator або спостереженням
  за його контрольованим персонажем/місцем водія.
  Гравець поруч не стає автором події. `engine_instigator` не є доказом авторства
  мережевого запиту; UID для нього навмисно не підставляється з поточного слота.
- Discord-повідомлення з назвою сервера, гравцем/UID, типом події та вимірами;
  SQLite-черга, повторні спроби та дедуплікація після перезапуску.

Наявність зв'язку з гравцем також не доводить використання стороннього ПЗ.
Стандартні бойові дії, GM, легальні моди й відновлення збереження можуть створювати
схожі події. Усі спрацювання мають вердикт `needs_human_review`.

## Швидко перевірити аналізатор

Потрібен Python 3.10 або новіший, сторонні бібліотеки не потрібні. Із кореня репозиторію:

```bash
python3 -m unittest discover -s tests -v
python3 examples/make_demo.py
python3 analyzer/checker.py --input examples/events-demo-0.jsonl --config config/analyzer.json --output runtime/demo-alerts.jsonl
```

Приклад містить **штучні** дані, не з цільового сервера. Очікуваний результат:
34 записи, 2 спрацювання — `unattributed_spawn_burst` і `explosive_damage_cluster`.
Штатне будівництво та багато hitzone-подій для одного об'єкта не створюють цих спрацювань.

## Discord та приклад телепорту

Окрему application/bot у Discord Developer Portal створювати **не потрібно**.
Достатньо webhook у каналі адміністрації. Інструкція: [DISCORD_UK.md](docs/DISCORD_UK.md).
Перегляд синтетичного сповіщення без мережевих запитів:

```bash
python3 examples/make_movement_demo.py
python3 analyzer/checker.py --input examples/events-movement-0.jsonl --config config/analyzer.json --output runtime/movement-alerts.jsonl
python3 notifier/discord_bot.py --input runtime/movement-alerts.jsonl --server-id server-1 --server-name "Server 1"
```

Три записи дають одне спрацювання: `[VEHICLE] DemoDriver`, `distance=702.195 m`,
`time_delta=1 s`, `AVG_SPEED=702.195 m/s`, `INST_SPEED=145.189 m/s`.
Сповіщення позначає можливий телепорт для ручної перевірки; воно не доводить,
хто ініціював переміщення. Легальні телепорти потребують серверного адаптера
скидання вимірювання: [MOVEMENT_UK.md](docs/MOVEMENT_UK.md).

## Встановлення на стенд

Докладні кроки: [docs/INSTALL_UK.md](docs/INSTALL_UK.md).

1. Відкрити `mod/ConflictAudit/ConflictAudit.gproj` у Arma Reforger Tools відповідної
   версії та скомпілювати скрипти. GUID у файлі — локальний ID проєкту, **не
   опублікований Workshop ID**.
2. Перевірити мод на окремій копії Conflict із вашим набором модів.
3. Переконатися, що з'являються `session_start`, `heartbeat` і контрольні події.
4. Аналізувати каталог журналів на хості або його копії:

```bash
python3 analyzer/checker.py --input /path/to/server/profile/ConflictAudit --config config/analyzer.json --output runtime/alerts.jsonl --follow
```

Логіка працює на сервері. Addon підключається як звичайний мод Reforger; клієнтам
може бути потрібен той самий addon. Відсутність RPC у цьому коді не означає
можливості приховано встановити довільні скрипти лише на сервер.

## Межі покриття

- Суто клієнтські об'єкти/ефекти сервер не бачить.
- Це не універсальний перехоплювач усіх native spawn/explosion/RPC операцій.
- Вибух без пошкоджень, який обходить спостережуваний тригер, може бути пропущений.
- Просторовий сенсор бачить окремі ділянки, а не всю карту безперервно.
- Новий об'єкт у ділянці може бути переміщеним або завантаженим об'єктом.
- Незнайомі моди будівництва потребують адаптерів та калібрування.
- Телепорт і повернення між двома вимірами, переміщення під час grace-періоду
  або нижче порогів можуть бути пропущені. Фізика й корекції реплікації можуть
  давати схожі стрибки; пасажири не включаються у сенсор руху техніки.
- За відсутності автора запис залишається без встановленого гравця.
- Скомпрометований сервер або мод із виконанням довільного серверного коду може
  обійти чи змінити такі сенсори та локальні журнали.
